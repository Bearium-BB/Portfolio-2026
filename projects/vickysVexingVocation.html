Overview

  • Role: Gameplay & UI programmer, plus VFX, on a team of 5.
  • Engine: Unreal Engine, built entirely in Blueprints.
  • Duration: about 2 months, 2026.

I worked across three areas: the logic behind the Gambling Gun, the enemy attack behavior and the UI that ties them together, and the visual effects that make it all feel good to play. Here's what I built and the problems I ran into along the way.

Gambling Gun

The Gambling Gun is built around a projectile system that I wrote from scratch. Holding the fire button checks a fire rate, and a multi-gate cycles through the list of projectile types. The default shot fires fast, while the stronger projectiles use longer delays to balance them. A "do once" gate blocks the gun until that delay has finished. It isn't the nicest solution, and a timer would be cleaner, but it works and was quick to build.

The gun's gamble comes from the shoulder buttons. RB picks a random special bullet for about two seconds before a cooldown resets it, and LB applies a random modifier to the character that is removed again when the cooldown ends.

GIF: gambling gun firing

Problem solved: switching weapons has to remove the modifier from the character, but a component can only be deleted by the object that owns it. So the gun casts to the player and tells the character to delete its own component. I also tried making the projectiles script objects to keep the gun tidy, but those can't spawn actors, so I went back to spawning actors directly.

Enemy AI

For the enemies I built the attack task inside the behavior tree. When an enemy gets close to the player, it sets a blackboard value that stops its movement and plays an attack animation, which is only a telegraph and doesn't hurt. About a second later it spawns a real overlap sphere, so the player has time to dodge, and anyone still inside takes damage while the screen shakes as the ball explodes.

The enemies use custom collision channels so overlaps only check against the right object types, which keeps them cheap. The checks run as a chain of fail states, a pattern a teammate suggested. It works for a short project, but it would turn into a mess as it grew, and I'd replace it with a controlling boolean next time.

GIF: enemy attack

UI Programming

I wired up the HUD, main menu and pause menu. The buttons use event dispatchers, so the menus just subscribe to them, and play and quit trigger a short animation before the scene changes. The UI for each weapon is chosen by a UI switcher that loads the right widget based on the weapon the player is holding, and an event dispatcher fires whenever the weapon changes so anything in the game can react.

The Gambling Gun's own UI is a set of percentage bars. They're driven by events instead of reading from the gun directly, so the widgets only need a value between zero and one and don't depend on the weapon. The same value also fills a reticle on the character, as a second piece of visual feedback.

  • Custom widgets: a button and a rich text block that other widgets reuse.
  • Teammates: the visual polish, the checkbox and the menu animation were done by others.

Portal Sequence

When you clear a room, a portal sequence plays: the screen shakes, lightning bursts out, a shockwave expands and three pillars rise and bob up and down, glowing ten times brighter to light up the room. The sequence is built from timelines in a Blueprint.

Problem solved: Niagara effects wouldn't spawn from inside a for loop, so the lightning is generated by a looping timer event that spawns it a bit at a time and a second timer that stops it.

GIF: portal opening

VFX & Materials

This was my first time doing VFX, so I started with two reusable materials: you give them any effect texture and they mask it, recolor it and control how brightly it glows. One drives opacity for softer edges, the other uses a mask.

From there I built the lightning, adapting a free pack from the Fab store. It distorts a texture's UVs with layered displacement and uses a color ramp to give the core and the outer glow different colors. The laser for a teammate's weapon scrolls two textures through each other and reads its color from a curve, so the beam can fade from a dark outline, to cyan, to yellow. The beam's length and width are parameters, so the same material works at any size. The shockwaves use a custom hollow cylinder mesh, so you never see the cap, with timelines controlling scale and fade.

Art & Lighting

I modeled the original ghost enemy, which teammates then re-UV'd and optimized. I also lit the scenes and set up the ground's normal, specular and metallic maps. The game looked flat before, and the lighting and VFX are a big part of what gives it atmosphere now.
